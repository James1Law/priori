Scenario 1 — Design notes:
  • Visual hierarchy through bar size: Goal bars are 32px tall with bold gradient and shadow. Initiatives are 26px, Epics 22px, Stories 18px. Each level gets progressively lighter. Flat items use green (distinct from the indigo hierarchy).
  • Auto-spanning parent: "Increase Activation" spans Q1–Q2 because its children (Onboarding in Q1, Analytics in Q2) define the range. The parent bar is not independently draggable to a smaller range than its children.
  • Collapse/expand: "Growth Analytics" is collapsed — it shows a single bar covering its children's aggregate span. "Reduce Churn" is collapsed at goal level.
  • Left sidebar indentation: Level 0 at 0px, Level 1 at 18px, Level 2 at 36px — compact enough for the 200px column while still showing hierarchy.
  • Flat items (green bars): "Safari Login Fix", "Privacy Policy Update", "API Docs" — no hierarchy badge, no expand button. Look identical to the previous roadmap behaviour.
  • "Collapse All" button in toolbar collapses all parents to show only top-level items + flat items.

Scenario 2 — Constraint design notes:
  • Constraint A — Child resize: When the user drags a child's edge past the parent boundary, the bar snaps to the parent edge. A red dashed boundary line and warning message appear. No toast needed — the visual feedback is immediate.
  • Constraint B — Parent shrink: When the user tries to shrink a parent past its children's aggregate span, the resize stops at the minimum bound. Red dashed marker shows the limit. The user must first move/shrink the children before the parent can shrink further.
  • Behaviour C — Parent move: Moving a parent by N quadrants shifts every descendant by the same N quadrants. Dashed ghosts show previous positions. All updates are batched into a single Supabase call.
  • Growing a parent is always allowed — extending the start or end of a parent doesn't affect children's absolute positions.

Scenario 3 — Scheduling design notes:
  • Action A — Scheduling a parent: Parent gets placed at the dropped position. Children remain unscheduled — the user schedules them individually within the parent's span. This avoids auto-placing children in arbitrary positions.
  • Action B — Child within parent: If a child is dropped within its scheduled parent's span, it's placed directly. Green checkmark confirms valid placement.
  • Action C — Child outside parent: If a child is dropped outside its parent's current span, the parent auto-extends to encompass the child. An amber highlight + message explain what happened. This avoids blocking the user's workflow.
  • Orphan children (parent unscheduled): If a child is scheduled but its parent isn't, the child appears in the timeline independently. When the parent is later scheduled, it auto-spans to encompass the child.

Scenario 4 — Deep nesting notes:
  • 4 levels visible: Goal (32px) → Initiative (26px) → Epic (22px) → Story (18px). Bar height and colour intensity decrease at each level, creating a clear visual hierarchy.
  • Subtasks (Level 4) hidden: Subtasks are too granular for a roadmap view. They're visible in the backlog and capacity views but not rendered on the timeline. This keeps the roadmap strategically focused.
  • Indentation caps at 54px: Level 0 = 0px, Level 1 = 18px, Level 2 = 36px, Level 3 = 54px. The 200px label column handles this comfortably.
  • Mixed expand states: Goal expanded, first Initiative expanded with its Epic expanded (showing Stories), second Epic collapsed, second Initiative collapsed. Users control exactly how much detail they see.
  • Story bars have no resize handles: Stories are the smallest schedulable unit on the roadmap. They can be moved but are typically sized to 1-2 quadrants.

Scenario 5 — Partially scheduled notes:
  • Unscheduled children in expanded view: When a parent is expanded and some children aren't scheduled, those children appear as amber-highlighted rows with a "Not yet scheduled" hint. This makes gaps visible in context.
  • Unscheduled panel context: Chips for children of scheduled parents include a "within [parent name]" context label, so the user knows where they belong.
  • Partially scheduled parents in the panel: The group header shows "2 of 3 children unscheduled" to communicate progress.
  • Click to place: Clicking the "Not yet scheduled" hint row opens a quick-place interaction (place at cursor position within parent bounds).
  • Period names: This scenario uses "Now / Next / Later" defaults — showing the roadmap works with any naming convention.
