UX Notes - Roadmap View

  • Sidebar: Fixed list of items with dates. Click to highlight bar in timeline.
  • Roadmap bars: Drag horizontally to move start date. Drag edges to resize duration.
  • Overlapping work: Bars can overlap vertically to show parallel work streams.
  • Today line: Red vertical marker showing current date.
  • Zoom levels: Week (detailed), Month (default), Quarter (high-level planning).
  • Colours: Auto-assigned or user-selectable per item.
  • Data model: Requires adding start_date and end_date fields to items.

Implementation Approaches

Two possible approaches for implementing the Roadmap view, with different trade-offs.

Option A: Simple Duration-Based

Items have a duration (in days/weeks) but no specific dates. Roadmap shows relative sequencing.

  • Simpler data model (just add duration_days)
  • No need for date pickers
  • Works well for rough planning
  • Can't set specific start dates
  • Less precise than real Gantt
  • Harder to plan around milestones

Option B: Full Date-Based

Items have explicit start and end dates. Full Gantt-chart functionality.

  • Precise scheduling
  • Can plan around milestones
  • Industry-standard UX
  • More complex data model
  • Requires date pickers
  • More UI complexity

Recommendation

  • Start with Option A for MVP - simpler to build and test.
  • Add full date support (Option B) later based on user feedback.
  • Roadmap is Phase 3 - focus on Roadmap Mode first.

Option C: Custom Time Buckets (Recommended)

Instead of calendar dates, users define their own time periods (quarters, sprints, releases, etc.). Items span across these buckets using a simple unit system - no date pickers needed.

Custom Buckets - Key Concepts

  • Flexible periods: Name buckets anything - Q1/Q2, Sprint 1/2/3, Release 1.0/2.0, Milestone A/B/C
  • Resizable columns: Drag the ⋮⋮ handle to make a bucket wider or narrower (represents relative time)
  • No dates required: Optional subtitle for context ("Jan - Mar") but not enforced
  • Bar positioning: Drag bars horizontally and resize with edge handles
  • Unscheduled items: Items without roadmap placement shown greyed in sidebar
  • Add buckets: Click + to add new time periods, click header to edit name

Final Design Decisions

Decisions Made

  • Scheduling items: Hover over empty row to see ghost bar, click to place. Items start unscheduled.
  • "Outside period" items: Show greyed out in overflow area. User re-places by hovering/clicking.
  • Mobile: Desktop-only feature. Mobile shows placeholder message encouraging desktop use.
  • CSV export: Disabled in Roadmap view. User must switch to Scoring/Backlog to export.
  • Initial state: All items start unscheduled (no bars). User explicitly places each one.
  • Bar sizing: Default to 1 bucket wide when placed. User can resize to span multiple.

Mobile: Desktop-Only Placeholder

On mobile devices, the Roadmap tab is hidden. If a user somehow reaches the roadmap view (e.g., via URL), they see a friendly placeholder encouraging them to open on desktop.
