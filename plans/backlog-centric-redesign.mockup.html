Planning Poker Shareability

The /estimate URL is the key shareable link for collaborative estimation:

  • Copy URL button in the estimation flow copies the /estimate URL
  • Late joiners land on the current item being estimated
  • Session state (current item, revealed votes) synced via Supabase Realtime
  • No items selected? Shows "Select items from backlog to start estimation" with link back
Copy URL Experience When in the estimation flow, the "Copy URL" button specifically copies the /estimate URL. A toast confirms: "Estimation session link copied! Share with your team to vote together."

Design Summary

Core Principles

  • Backlog is home: All items live in a central list that's always accessible
  • Features are actions: Score, Estimate, Add to Roadmap are things you *do* to selected items
  • Progressive disclosure: Columns/badges only appear when data exists (no empty "—" everywhere)
  • Item drawer: Click any item to see full details, scores, estimates, and edit status
  • Dedicated flows: Actions like Planning Poker open a focused experience with breadcrumb navigation back
  • Shareable URLs: Each flow has a clean URL (/estimate, /score) for easy collaboration

Key Features

  • Sorting: Sort by any column (Score, Estimate, Status, Period, Title) or manual drag order
  • Multiple cutoffs: Add multiple cutoff lines for different milestones (Sprint 1, Sprint 2, etc.)
  • Period labels: Roadmap periods become metadata on items - assign from drawer, action bar, or roadmap view
  • Status tracking: Simple To Do / In Progress / Done per item
  • Filters: Filter by status, has estimate, has score, on roadmap, by period

What This Enables

  • Flexibility: Use only the features you need (just scoring? just estimates? both?)
  • Scalability: Easy to add new actions (Import, Duplicate, Archive, etc.)
  • Collaboration: Share /estimate URL for Planning Poker sessions with your team
  • Future accounts: Sessions become "projects" that persist in your account
  • Paywall potential: Chat, advanced frameworks, team sharing, multiple scenarios could be premium

Decisions Made

  • Roadmap: View toggle (List / Roadmap) - keeps visual drag-and-drop experience
  • Scoring: Dedicated flow (like estimation) - but collaborative free-for-all, not voting-based
  • Planning Poker: Late joiners land on current item and can vote immediately
  • Multiple scenarios: Parked for v2 - adds complexity, could be premium feature

Open Questions

  • Cutoff persistence: Should cutoffs survive re-sorting, or reset to manual order?
  • Keyboard shortcuts: How important for power users?
  • Period creation: Create periods in roadmap view, or also from action bar?

Migration Path

This is a significant UX change from the current tab-based model. A phased approach could work:

  1. Add status field and item drawer (minimal disruption)
  2. Add multi-select and action bar
  3. Add sorting and multiple cutoffs
  4. Convert tabs to view toggles (List / Roadmap)
  5. Move scoring and estimation into dedicated URL-based flows
  6. Add period labels as item metadata
