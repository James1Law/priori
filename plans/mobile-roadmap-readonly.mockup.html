Mobile Roadmap — View-Only

A view-only mini Gantt for mobile in both portrait and landscape. Users can view the timeline and tap items to edit dates via the ItemDrawer. No drag-and-drop — the desktop Gantt uses mouse-only events that are incompatible with touch.

Design Principles

  • View-only always — No drag-and-drop or resize handles on mobile (desktop Gantt uses onMouseDown with 8px handles and 18-28px bars, far below Apple's 44px minimum touch target)
  • Tap to edit via ItemDrawer — Tapping an item opens the existing ItemDrawer with date fields, consistent with all other modules
  • Same zoom controls — 3M / 6M / 1Y / Fit presets work on mobile too
  • Full information — Same data as desktop, just presented for touch viewing
  • Familiar interaction — Scroll, pan feel native on mobile
  • Landscape bonus — Wider viewport shows more of the timeline without scrolling
PORTRAIT VIEW

Pannable Mini Gantt

The desktop Gantt chart, simplified for touch. Item labels pinned on the left, timeline scrolls horizontally. Tap any bar to open the ItemDrawer.

Strengths

  • Closest to desktop — familiar mental model
  • Shows temporal relationships at a glance
  • Overlapping items are visually clear
  • Zoom presets work naturally

Considerations

  • Small bars can be hard to tap precisely
  • Requires horizontal scrolling (not always intuitive)
  • Bar labels may be too small to read at some zoom levels

LANDSCAPE VIEW

Wider Viewport, Same View-Only Gantt

In landscape orientation, the same read-only mini Gantt benefits from the extra width. More of the timeline is visible without horizontal scrolling. Same interaction model — tap to open ItemDrawer.

Why view-only in landscape too? The desktop Gantt uses mouse-only events (onMouseDown) with 8px resize handles and 18-28px bar heights, which are far below Apple's 44px minimum touch target. Adding touch support would require a complete rewrite of the drag/resize system. Landscape simply gives a wider, more comfortable view of the same read-only chart.

Recommendation

View-Only Mini Gantt + ItemDrawer

Use the pannable mini Gantt as a view-only chart in both portrait and landscape. It preserves the Gantt mental model and shows temporal overlaps — the whole reason people use a roadmap. The key adaptations for mobile:

  • No drag, no resize handles — purely visual. The desktop Gantt uses onMouseDown with 8px resize handles and 18-28px bar heights, far below Apple's 44px minimum touch target. Adding touch support would require a complete rewrite.
  • Tap any bar → ItemDrawer — the same full-screen side panel used in Backlog, Capacity, and all other modules. Slides in from the right with editable start/end date fields using native date pickers.
  • Consistent UX — using ItemDrawer (not a bottom sheet) means the same interaction pattern across every module in the app
  • Pinned item labels on the left so you always know which row is which while scrolling the timeline
  • Zoom presets (3M/6M/1Y/Fit) in a compact pill bar — same as desktop
  • "Scroll to pan" hint disappears after first interaction
  • Today marker stays visible for orientation
  • Unscheduled items shown at the bottom with amber background — tapping opens drawer to set dates
  • Landscape — same view-only Gantt, just wider and more comfortable. No additional features, just more timeline visible without scrolling.

This gives mobile users the same roadmap view as desktop — they're just reading it instead of dragging things around. The date picker in the ItemDrawer is actually easier than drag-and-drop for precise date entry anyway.

Implementation Notes

  • Reuse the existing getRoadmapDateTree(), getViewRange(), and dateToPixel() utilities — same data, different renderer
  • Create a new RoadmapMobileView component (not the deprecated placeholder)
  • On bar tap, open the existing ItemDrawer — consistent with Backlog, Capacity, and all other modules
  • Use CSS overflow-x: auto with -webkit-overflow-scrolling: touch for smooth panning
  • Item labels use position: sticky; left: 0 to stay pinned during horizontal scroll
  • No new database changes needed — reads the same start_date/end_date fields
  • The Gantt inner width should scale with zoom level (e.g. 600px for 3M, 900px for 6M, 1400px for 1Y)
  • View-only in both portrait and landscape — no touch-based drag/resize in either orientation
