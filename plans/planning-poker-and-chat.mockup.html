Design Notes

Planning Poker View

  • Position: New tab between "Scoring" and "Backlog"
  • Flow: Scoring → Estimates → Backlog → Roadmap
  • Fibonacci sequence: 0, 1, 2, 3, 5, 8, 13, 21 plus ? (uncertain) and ☕ (break)
  • Hidden votes: Cards are face-down until all participants vote or facilitator reveals
  • Consensus: When revealed, highlights agreement or shows distribution for discussion
  • Queue: Work through items one-by-one; can skip or reorder
  • Integration: Estimates stored per-item and shown in Backlog/Roadmap views

Chat Feature

  • Access: Click participant count indicator to toggle chat panel
  • Position: Right sidebar, collapsible
  • Persistence: Messages stored in Supabase, synced via Realtime
  • Notifications: Unread badge when new messages arrive (chat closed)
  • Context: Particularly useful during Planning Poker for discussing estimates
  • Mobile: Full-screen modal overlay on mobile devices

Mobile Experience

  • Planning Poker: Fully functional on mobile — 5x2 card grid optimised for thumb reach
  • View Selector: Compact 4-tab selector (Score, Estimate, Backlog, Map) replaces desktop tabs
  • Chat: Opens as full-screen modal overlay with native keyboard handling
  • Bottom Bar: Primary actions (Skip, Reveal, Accept) in fixed bottom bar for easy access
  • Team Votes: Compact horizontal layout showing all participants
  • Item Queue: Collapsible "Up Next" section showing estimation progress
  • Real-time: Same Supabase Realtime sync — votes and chat update instantly across devices
  • Use Case: Join sprint planning from anywhere — commute, coffee shop, working from home

Database Changes Required

  • items.story_points — Integer, nullable (estimate value)
  • items.estimation_status — Enum: 'pending', 'in_progress', 'completed'
  • estimation_votes — Table for storing individual participant votes
  • messages — Table: id, session_id, participant_name, text, created_at
  • sessions.estimation_mode — Boolean to enable/disable estimation feature

Implementation Complexity

  • Planning Poker: Medium-high — new view, voting logic, reveal/consensus UI, real-time sync
  • Chat: Medium — leverages existing Realtime infrastructure, new table + component
  • Integration: Low — displaying estimates in existing views is straightforward
