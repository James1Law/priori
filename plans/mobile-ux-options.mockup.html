What Users Actually Do

The typical user workflow is:

  1. Setup (once): Choose framework
  2. Add items (few times): Enter titles
  3. Score items (many times): Adjust scores, compare
  4. Iterate: Add more items, adjust scores

The scoring phase is 80% of the interaction but currently gets pushed below the fold on mobile.

Key insight: The framework selector and add form are "setup" tasks that don't need constant visibility during the scoring phase.

My Recommendation

Option A: Bottom Input Bar

Your instinct is correct: the current stacked layout prioritises setup over the actual work. On mobile, screen real estate is precious, and the most frequent action (scoring items) should get prime position.

The bottom input bar pattern (like iOS Messages, Slack, etc.) is the best fit because:

Items First

Users see their items immediately without scrolling. The scoring interface gets full attention.

Quick Adding

The persistent bottom bar means adding a new item is always one tap away, no scrolling required.

Familiar Pattern

Users already know this pattern from messaging apps. Zero learning curve.

Low Complexity

Can be implemented with minimal changes to existing code. Just repositioning, not restructuring.

Implementation approach: Move the framework selector into the header (as a compact dropdown showing current selection). Move the item input to a sticky bottom bar on mobile only. Desktop layout remains unchanged.
