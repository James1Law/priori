Mobile design notes:
  • Vertical period cards: Each period is a self-contained card. Items spanning multiple periods appear in each relevant card with overflow indicators ("← From Q1", "Continues → Q2").
  • Mini timeline bars: Thin horizontal bars (6-8px) show relative position within the period's 4 quadrants. Parent bars are slightly thicker (8px) with bolder colour.
  • Tap to expand/collapse: The ▾ toggle works the same as desktop. Indentation (0.75rem per level, max 2.25rem) provides hierarchy context within the narrow screen.
  • Tap item for actions (right frame): Tapping an item highlights it and reveals action buttons — "View Details" opens the item drawer, "Open in Backlog" navigates to backlog with that item selected.
  • Read-only for v1: No drag/resize on mobile. The empty period shows "Add items from the backlog on desktop" to set expectations. The FAB (+) creates new items but doesn't schedule them — scheduling happens on desktop.
  • Unscheduled section: Same grouped layout as desktop, with larger touch targets (min 36px chip height) for tappability.
  • Collapsed default: Right frame shows all parents collapsed — the typical mobile view. Users expand only what they need. This keeps the scroll manageable.

Landscape / tablet notes:
  • Hybrid layout at 640px+: Item label and timeline bar sit side-by-side (grid: 180px label + 1fr bar), similar to the desktop layout but within vertical period cards.
  • Sub-period labels: Period headers show month names (Jan, Feb, Mar) as reference points for the bar positions.
  • Same touch interactions: Tap to expand/collapse, tap item for actions. No drag/resize even on tablet for v1.
  • Progressive enhancement: At 1024px+ (desktop), switch to the full horizontal timeline. This is the existing `sm:` breakpoint pattern used elsewhere in the app.
